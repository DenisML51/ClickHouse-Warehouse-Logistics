# Система оптимизации логистики складов

Курсовой проект по СУБД. Система моделирования и оптимизации перемещений товаров между складами на базе ClickHouse (MergeTree).

## Описание задачи

Есть логистическая сеть из N складов, представленная в виде графа (ClickHouse MergeTree). На складах распределены **100 000 объектов** K типов (K < 100). Заказчики последовательно забирают объекты со складов согласно **Листу заявок**.

### Ключевые ограничения по условию:

- **100 000 объектов** распределены по складам неравномерно
- **Сумма всех заявок = 100 000** (все объекты должны быть забраны)
- K типов объектов, **K < 100**

### Правила симуляции:

1. **Лист заявок** — последовательность: `(№ заявки, тип товара K, количество T, склад A)`
2. За **1 ход** заказчик забирает со склада A товар типа K количества T
3. За **1 действие** можно перемещать товары только **одного типа K**
4. Если выполнить заявку не получается — **штраф +1** за каждый ход ожидания
5. Если на ходу N висит M невыполненных заявок — штраф **+M**
6. Цель: **минимизировать общий штраф**

### Результат работы программы:

**Таблица перемещений** — ответ алгоритма:
`(Склад A, Склад B, тип товара K, количество T)`

## Установка и запуск

### 1. Установка зависимостей (через uv)

```bash
# Установить uv (если не установлен)
pip install uv

# Синхронизировать зависимости
uv sync
```

### 2. Запуск ClickHouse

```bash
docker-compose up -d
```

### 3. Запуск приложения

```bash
uv run main.py
```

## 6 тестовых сценариев

Каждый тест содержит **ровно 100 000 объектов** и заявки на сумму **100 000**.

| # | Название | Описание | Топология | K типов |
|---|----------|----------|-----------|---------|
| 1 | Идеальный случай | Товары уже на нужных складах (штраф=0) | Звезда (10) | 10 |
| 2 | Линейная магистраль | Все товары на складе 1, заявки на складе N | Цепочка (10) | 5 |
| 3 | Центральный хаб | Товары на периферии, заявки в центре | Звезда (8) | 8 |
| 4 | Кольцо с разбросом | Неравномерное распределение | Кольцо (12) | 6 |
| 5 | Сетка с множеством типов | 50 типов товаров (K<100) | Сетка 5x4 | 50 |
| 6 | Случайный сложный | Концентрация на 3 складах | Случайный (15) | 15 |

## Использование

### Главное меню

После запуска доступны опции:

1. Показать информацию о всех тестах
2. Загрузить тест (1-6)
3. Показать граф складов
4. Показать инвентарь
5. Показать лист заявок
6. Запустить симуляцию (автоматический режим)
7. Запустить симуляцию (интерактивный режим)

### Интерактивный режим

В интерактивном режиме на каждом шаге доступны команды:
- `Enter` — следующий шаг
- `l` — показать логи складов
- `i` — показать текущий инвентарь
- `a` — переключиться в автоматический режим
- `q` — остановить симуляцию

## Таблицы ClickHouse

### Входные данные
- `object_types` — типы объектов (K < 100)
- `warehouse_graph` — граф складов (рёбра)
- `initial_inventory` — начальное распределение товаров
- `order_list` — лист заявок

### Результаты
- `movements` — таблица перемещений (ОТВЕТ на задачу)
- `penalties` — штрафы
- `test_metadata` — метаданные тестов

## Алгоритм оптимизации

Используется **предиктивный жадный алгоритм**:

1. Приоритет — выполнение текущих активных заявок
2. Поиск ближайшего склада с нужным товаром (алгоритм Дейкстры)
3. Пошаговое перемещение товара по кратчайшему пути
4. Проактивная подготовка к будущим заявкам
